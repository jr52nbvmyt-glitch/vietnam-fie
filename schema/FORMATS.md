# Record formats

Everything `scripts/fie.py` reads is defined here. The script checks these formats; if a file breaks one, `fie.py check` says where. Read this before writing any part.

## 1. Where things live

| Path | What | Who writes it |
|---|---|---|
| `memos/NNN/manifest.toml` | The memorandum's structured facts: provisions, variables, phases changed | You, in Part 1; refined in Parts 2–3 |
| `memos/NNN/sources.md` | Numbered sources for `[S#]` tags | You, in Part 1 (and later parts if needed) |
| `memos/NNN/part1.md` · `part2.md` · `part3.md` | The memorandum, as written. Never edited after its part is finished | You |
| `memos/NNN/chapters/Pk.md` | This memo's edited copy of each chapter it changes | `fie.py chapters` copies; you edit; `fie.py finish` stamps and promotes |
| `history/chapters/Pk.md` | The war: one chapter per phase, the only copy of events | `fie.py finish` (promotion) and BASELINE |
| `history/phases.toml` | Phase list and dates | Checkpoints (G2) |
| `history/endstate.toml` | The end state of the war | You, when a part changes it |
| `history/TRAJECTORY-LOG.md`, `positions.md`, `persons.md`, `directives.md`, `gaps.md` | Registers | `fie.py` only, from blocks in your text |
| `reviews/CPnn`, `reviews/MTnn`, `reviews/TNA` | Checkpoints, meta-checkpoints, the Theater Needs Assessment | You |
| `revisions/Rnn` | Chapter revisions without a provision (VETO) | You |
| `errata/Enn.md` | Corrections to finished records | You |
| `build/` | Generated views: index, cards, ledgers, events, War History, reading copies, packs | `fie.py` only. Never edit; rebuild |

**Never edit** a finished part, a register, or anything in `build/`. A finished part is corrected by an erratum; a register by a new entry; `build/` by `fie.py build`.

## 2. Work tokens and IDs

A **work token** names a piece of work: `005` (memorandum), `000` (baseline), `CP01` (checkpoint), `MT01` (meta-checkpoint), `R01` (revision), `TNA`.

| ID | Form | Example |
|---|---|---|
| Provision | `P` + memo + letter | `P005a` |
| Finding | `F` + memo + `-` + n | `F005-7` |
| Employment concept | `EC` + memo + `-` + n | `EC005-3` |
| Causal chain | `C` + memo + `-` + n | `C005-2` |
| Event | `EV` + work + `-` + n | `EV005-4`, `EV000-31`, `EVCP01-2` |
| Position / reversal | `POS` / `REV` + work + `-` + n | `POS005-1`, `REV012-1` |
| Directive | `DIR` + work + `-` + n | `DIRMT01-3` |
| Gap | `G-` + n | `G-12` |
| Erratum | `E` + nn | `E03` |

Numbers within a memo start at 1 and run in order of first appearance. An ID is never reused.

## 3. Provenance tags

Every figure carries one. The checker warns on untagged figures in §1 and rejects malformed tags everywhere.

| Tag | Meaning |
|---|---|
| `[U]` | Stipulated in the provision message |
| `[S3]` | Published specification or source, number 3 in this work's `sources.md` |
| `[H]` or `[H3]` | Historical record (optionally with a source number) |
| `[E: basis]` | Estimate, with its basis stated |
| `[D]` | Derived from other tagged figures in the same passage |
| `[X-005]` | A judgment generated by this exercise, in work 005. Never cited later as a measurement |
| `[M005]` | Taken from memo 005's record; carries that record's own provenance |

An `[X-…]` figure stays an `[X-…]` figure forever. A later memo may build on it, but must keep the tag and may not present it as data (A13).

## 4. Markers

HTML comments are invisible in the reading copies.

| Marker | Where | Meaning |
|---|---|---|
| `<!-- audit -->` | Top of each part | The script writes the computed audit line on the next line |
| `<!-- card:figures P005a -->` … `<!-- /card -->` | Part 1, per provision | Key figures for the card |
| `<!-- card:negative P005a -->` … | Part 1 | The negative specification, condensed |
| `<!-- card:denies P005a -->` … | Part 1 | What it denies the enemy, one or two lines |
| `<!-- card:verdict P005a -->` … | Part 1 | The honest verdict |
| `<!-- card:findings -->` … | Part 2 | The findings register table |
| `<!-- card:concepts -->` … | Part 2 | Employment concepts on one line, then abandoned ones |
| `<!-- card:interactions -->` … | Part 2, optional | One line per compound pairing with an earlier provision |
| `<!-- cd:none -->` | Part 2 §2 Part C | Searched, no counter-directional finding (say what you ruled out) |
| `<!-- spe:modest -->` | Part 2 §2 Part C | Searched; the honest assessment is modest |
| `<!-- chapter P2 -->` | Part 3, a revised phase | The script inlines this memo's edited chapter here in the reading copy |
| `<!-- null P4 -->` | Part 3, an unrevised phase | The stated null follows |
| `<!-- ripple-addressed -->` | Inside a null | The null addresses the moved end vector of the phase before it |
| `<!-- initiative -->` | Part 3 | Marks the enemy's unprovoked decision (G3) |
| `<!-- log -->` … `<!-- /log -->` | Part 3 | This memo's Trajectory Log entry |
| `<!-- positions -->` … `<!-- /positions -->` | Any part or review | Lines appended to `history/positions.md` |
| `<!-- persons -->` … `<!-- /persons -->` | Part 3 or review | Lines appended to `history/persons.md` |
| `<!-- directives -->` … `<!-- /directives -->` | Reviews | Lines appended to `history/directives.md` |
| `<!-- gaps -->` … `<!-- /gaps -->` | TNA, reviews | Lines appended to `history/gaps.md` |
| `<!-- swept -->` … `<!-- /swept -->` | Checkpoints | Variable IDs swept in the interaction sweep |

Register lines are bullets in the register's own format (see the head of each register file).

## 5. Required headings

**Part 1** — per provision: `## §1.<n> <Designation> — P005a`, then `### D1 · …` through `### D16 · …` (field names in `procedures/PART1.md`).

**Part 2** — `## §2 Part A — Integration` · `### Employment concepts` with `#### EC005-1 · <name>` (add `(abandoned)` to the name of an abandoned concept) · `## §2 Part B — Channels` with one `### <channel>` per channel, named exactly: Displacement · Bottleneck migration · Own-force opportunity cost · Counterfactual erasure · Perverse effect · Anticipation · Enemy detection and learning · Enemy adaptation cost · Cross-boundary feedback · Open channel · `## §2 Part C — Counter-directional finding and strongest positive effect` · `## §2 Findings register` · `## §3 Changes to existing forces`.

A finding is a paragraph that opens with its bold ID: `**F005-7** (SECURE) …`. The counter-directional finding opens `**F005-12 · Counter-directional** …`; the strongest positive `**F005-13 · Strongest positive** …`.

**Part 3** — `## §4.0 The course of the war` · one `## §4.Pk <phase title>` per phase in `history/phases.toml` · `## §4.H Historical comparison` · `## §4.N Net assessment and end state` · `## §5 Delta ledger` · `## §6 Changed / not changed` with `### What has changed` and `### What has not changed` as bullet lists.

A revised phase section holds `<!-- chapter Pk -->` and then `### Mechanism` · `### Enemy response and initiative` · `### Causal chains` · `### Downstream` · and, from the phase named by `clock_from_phase` on, `### Clock`. An unrevised phase section holds `<!-- null Pk -->` and the null.

A causal chain is a paragraph that opens `**C005-1** [lag]`, where lag is `immediate`, `weeks`, `months` or `war-shaping`, followed by its links joined with `→`. Three arrows reach link 3.

## 6. Manifest (`memos/NNN/manifest.toml`)

See `templates/manifest.toml`. Fields the script reads: `memo`, `title`, `received`, `status` (script-owned), `phases_changed` (script-owned, via `fie.py chapters`), `links`, `[deviation]`, `[[provision]]` (`id`, `designation`, `category`, `quantity`, `ceiling_spaces`, `arrival`, `in_service`, `systems`, `status`), `[[push]]` (`provision`, `var`, `band`, `note`), `[[depend]]` (`provision`, `var`, `note`), and optional `[[status_change]]` (`provision`, `status`, `date`, `note`).

Variables come from `schema/VARIABLES.toml`; bands run −3 to +3.

## 7. Chapters (`history/chapters/Pk.md`)

```
+++
phase = "P2"
title = "The main force war"
dates = "Aug 1965 – Dec 1967"
last_revised = "005"

[end_vector]
"POP.night_control" = 1
"ARVN.effectiveness" = 2
# … every variable marked vector = true, in bands against the historical state at the phase's end
+++
# Phase II — The main force war (Aug 1965 – Dec 1967)

Overview prose: the shape of the phase as it now runs.

## EV000-14 · The Ia Drang campaign · 14–18 Nov 1965 · Ia Drang valley, Pleiku Province · HIST-ALT · 000,005
The event, told to the §4 specificity standard.

## EV005-3 · Operation SILVER LANCE · 2–9 Mar 1966 · Bong Son Plain, Binh Dinh Province · NEW · 005
…

## How the phase ends
Closing prose.
```

An event header has five fields after the ID, separated by ` · `: title · date · place · origin · works. Origin is one of:

| Origin | Meaning |
|---|---|
| `HIST` | Historical, unchanged |
| `HIST-ALT` | Historical, altered (say how and by what in the text) |
| `CANCELLED` | Historical, no longer happens (say why) |
| `NEW` | Created by the provisions |
| `FREE` | Free play (G4): caused by no provision and not historical |

A historical accident is `HIST`, not `FREE`. Events stay in date order. An event is never deleted: mark it `CANCELLED`. You set the origin; the script maintains the works field, adding the current work to every event you create or change.
